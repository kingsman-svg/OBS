# 分阶段实施路线

推进方式已明确：在同一个工程内分步骤增加能力，用 Git 管理每一步。
以下是阶段方向，每个阶段继续拆成小步骤；AI 场景与硬件要求明确后再调整具体实现。
每一步直接在本工程实现和运行验证，简化 Qt 界面随模块逐步完善。

| 阶段 | 工作 | 完成依据 |
| --- | --- | --- |
| 0：基线与边界 | 初始化 Git；审计实际调用链和依赖；明确首个业务场景；确定构建方式、模块职责、帧/音频/错误契约 | 有 Git 基线、可定位到源文件的技术地图和首步骤实现设计 |
| 1：网络与登录 | 重新设计 HTTP 登录接口，采用简单 MVC；实现异步请求、超时、取消、登录状态及退出；再实现真实认证服务 | 客户端请求与界面行为可验证；真实认证服务接入单独验收；类图和时序图同步完成 |
| 2：音视频采集 | 依次实现摄像头、麦克风、系统音频和屏幕/窗口；统一格式、时间戳及生命周期契约 | 在本工程完成采集与预览/监听；重复启停、切换设备和失败返回明确 |
| 3：FFmpeg 封装 | 按资源管理、解封装/解码、格式转换、音频处理、编码、封装/输出逐步拆分 | 生成可播放文件；验证时间戳、音画同步、排空与正常收尾；推流单独验证 |
| 4：GPU 美颜链路 | 建立 D3D11 资源边界和效果接口；先跑通单效果，再连接采集、效果、合成、预览和编码 | 预览与实际输出均包含美颜；记录帧率、处理耗时、回读成本和显存使用 |
| 5：AI 部署 | 选定一个模型任务与运行环境；完成输入预处理、模型加载、推理、输出适配及部署方式 | 能复现部署并获得实际结果；记录模型版本、延迟、内存/显存和失败行为 |
| 6：AI Agent | 围绕一个明确任务设计工具；复用应用层能力，处理参数校验、执行结果、取消与超时 | 完成一个可重复演示的任务闭环，并记录工具调用结果 |
| 7：集成与交付 | 整理逐步形成的 Qt 界面、配置、依赖和文档；验证媒体链路与 AI 同时运行 | 新环境可按文档运行；完成完整场景验证并注明限制 |

## 每一步的推进顺序

1. 说明本步目标、对应旧代码与封装边界。
2. 在同一工程内实现一个小范围的变化。
   每新增/修改一个类，维护对应 UML 类图；每完成/修改一个流程，维护对应 UML 时序图。
3. 构建并运行相应功能，记录本步验证结果。
4. 使用 Git 提交本步成果，再继续下一步；需要时为可运行的阶段版本添加标签。

## 首个实现前需要产出的设计

1. 当前场景已确定为 HTTP 登录：输入账号密码，处理成功、失败、超时与取消，再清除本地会话。
2. 该场景的输入输出、状态转换、线程归属与资源所有权。
3. 与 CourseStudio 和既有 Demo 的对应代码及复用判断。
4. 最小实现范围和运行验收步骤。
