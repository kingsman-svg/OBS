# 第020步：混音增益平滑、立体声限幅与设备时钟漂移补偿

在现有AudioMixer/AudioResampler内实现前三项DSP优化。增加普通StereoLimiter作为混音总线处理对象，不增加生产线程、MVC、独立Demo或测试程序。Publisher的ABR/编码前队列策略、Player的自适应播放缓冲不变。

## 对象与线程

Controller拥有AudioMixer，GUI消费两个WasapiCapture线程的有界PCM邮箱。每路AudioMixTrack拥有独立AudioResampler/SwrContext和增益过渡状态，AudioMixer另拥有一个StereoLimiter。以上处理仍在Controller原有串行调用中执行，不跨线程操作swr，也不在采集回调里访问GUI。

链路：WASAPI原始Float32/QPC → 每路重采样及漂移补偿 → QPC对齐 → 每路逐采样增益 → 浮点相加 → 左右联动限幅 → 原10ms契约 → MediaTimeline → 编码。

## 增益平滑

- `setControl`保留用户增益/静音设置；有效目标为静音0、非静音用户增益。
- 运行中改变目标时，从当前实际增益出发，用480个采样帧（10ms）线性过渡；再次操作以当前值重新计算，不从旧目标起跳。
- 左右使用同一增益。每个输出样本位置推进一次，缺包、静音也消费时间，恢复不重放旧包。
- begin保留用户设置并重置过渡状态，初始直接采用本轮有效目标；设备突然失败仍按原路径撤路，不声称所有源跳变都经过淡出。

## 立体声联动限幅

`StereoLimiter`只接受480帧的48kHz立体声Float32包，允许混音输入超出±1。每次保留当前包，用下一包前240帧作为5ms预读。左右绝对峰值的最大值决定共同增益，样本峰值目标0.98。

1. 对当前480帧和未来240帧计算所需增益`min(1, 0.98/peak)`。
2. 反向约束相邻增益，下降斜率最多1/240每采样，在未来峰值到达前完成衰减。预读之外的峰值无法在该斜率约束下影响当前样本。
3. 正向以50ms时间常数指数释放，取不超过所需包络的增益，同时作用左右声道；保留立体声比例。
4. 最终有限性/±1保护仅作异常兜底，单独计数。`clippedSamples()`兼容旧接口但改为明确统计限幅前超幅采样值；另报限幅帧数、当前增益与输出保护次数。

首包仅缓存，下一包才输出前一包，不插入伪造起始静音。输出保留原包QPC/不连续标志，而非未来参考包时间。finish用零作未来参考，仅交付最后有效包一次；clear丢弃预读。GUI积压跳过时间时也撤掉过期预读包，不在追赶后又输出旧音频。时间戳有缺口时不跨缺口借未来峰值。

这是样本峰值限幅，没有过采样真峰值检测、响度归一化、AGC或降噪。指标不能推广为所有素材的听感改善或编码后真峰值保证。

## 采集侧采样时钟漂移补偿

WASAPI的QPC时间对应包的首个采样帧。设备即使都标称48kHz，实际时钟也可能相对QPC偏快/偏慢，因此固定标称采样率转换不能保证长期对齐。

1. configure时设置`SWR_FLAG_RESAMPLE`，同为48kHz也先建立滤波器，避免首次软补偿才重建并丢失库存。正常转换因此允许首包略短，尾部由drain补齐。
2. 重复/倒序时间戳不推进滤波状态。格式变化、显式discontinuity，或相邻包相对上一包帧长出现超过5ms的真实间隔跳变，重建连续段；不再根据会话累计偏差丢包/重建。
3. 只用可信设备时间，每至少1秒比较QPC间隔与累计输入样本的标称时长：`ppm=(QPC时长/标称时长-1)*1e6`。正值表示设备偏慢，需要多生成少量输出样本；负值相反。
4. 频差估计采用当前20%＋历史80%。相位误差由可信QPC对应的目标输出量，减去已输出样本及`swr_get_delay`滤波库存得到，避免把滤波等待误判成漂移。
5. 目标修正为频差加4秒收敛的相位反馈，限制±1000ppm；未量化控制命令每次最多改变100ppm。以96000个输出样本（2秒）为补偿距离，每秒刷新`swr_set_compensation(delta,distance)`；整数delta约10.4ppm一步，实际相邻提交允许有一个量化步长误差。
6. 估计时间戳不驱动校正，暂停已有软补偿，恢复可信时间后重新建立估计基线；超过2000ppm的窗口视为异常观测，同样暂停学习，不以极端重采样追赶。不是自动补救任意丢包/错误设备时间。
7. 输出时间戳仍由连续实际输出采样数产生，采集QPC不被篡改。不靠周期性丢整包或补整段静音完成微小漂移修正。普通结束先排空滤波器，保留本轮诊断；下一轮begin/clear重置估计、命令和统计。

补偿覆盖采集→混音一侧，未新增播放设备的异步重采样器。真实断包仍通过不连续标记/补零和既有有界队列处理，不能当作漂移混在一起纠正。

## 延迟、启停与诊断

Controller begin混音后启动采集线程，原定时交付调用push/takeFrames。仍留80ms对齐窗口；5ms样本预读按10ms包交付时额外保留一包，因此正常输出比原混音多等待约一包。实际何时交付还受GUI调度影响；原MediaTimeline总等待120ms包含这些前置等待，不把80+10+120相加。联合模拟已核对该预算下没有音频丢弃，未在本步声称实测完整端到端延迟不变。

普通stop：采集线程退出 → Controller取尾包 → AudioMixer.finish → 每路swr.drain → 剩余混音 → limiter.drain → MediaTimeline.finish → 编码排空。退出登录：clear同时丢滤波、混音队列和限幅预读，不输出旧音频。重启重新begin，用户音量/静音保留，DSP历史和计数清零。

原混音状态标签显示限幅前超幅、限幅帧数、总线增益、输出保护，以及两路时钟ppm/修正ppm/相位误差/校正与重建次数。估计/异常时间显示等待可信时间。界面无新增操作控件。
